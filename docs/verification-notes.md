# 화면 검증 기록

## 2026-08-18: 대관 확인·프로그램 안내 단순화

데스크톱(1280×720) 전체 화면에서 `booking.html`은 신청서·시간표 탭 없이 **대관 확인** 제목, 캘린더, 대관 일정 상태 안내만 표시되는 것을 확인했다. `programs` 화면은 기존의 `문화로 만나는 이번의 시간` 제목과 소개 문단 없이 프로그램 필터와 목록·달력 전환부터 바로 시작되는 것을 확인했다.

모바일(375×812)에서도 대관 캘린더는 단일 영역으로 표시됐고, 프로그램 안내는 제거 요청된 제목·설명 없이 필터와 목록·달력 제어를 세로로 배치해 가로 스크롤 없이 확인했다.

GitHub 저장소의 Pages 설정은 아직 비활성 상태여서, 이전 정적 배포 작업은 Pages 배포 생성 단계에서 404로 실패했다. Pages 활성화와 Apps Script 재배포가 끝난 뒤에는 GitHub Pages 실제 주소에서 대관 데이터·프로그램 데이터·관리자 사진 업로드를 다시 확인해야 한다.

## 2026-08-18: 프로그램 안내 홈 복귀 링크 여백

프로그램 안내에서 홈으로 돌아가기 링크를 별도 행으로 감싸고, 아래 프로그램 필터 앞에 데스크톱 40px·모바일 28px의 여백을 적용했다. 1280px 및 375px 화면에서 홈 복귀와 프로그램 영역이 붙어 보이지 않으면서도 화면 상단의 리듬이 과도하게 늘어나지 않는 것을 확인했다.

## 2026-08-18: GitHub Pages 공개 배포

`https://nyjculturalhouse.github.io/nyj-cultural-house-club/`에서 정적 홈 화면이 정상적으로 열리고, 출석·공간 이용 예약·외부활동 공유·프로그램 안내의 공개 진입점이 표시되는 것을 확인했다. `programs.html`은 Apps Script 조회 후 현재 공개 프로그램이 없다는 상태로 전환되어, 정적 페이지의 데이터 요청과 빈 상태 처리가 동작하는 것을 확인했다.

`booking.html`은 신청서·시간표 없이 캘린더만 표시됐으며, Apps Script에서 조회한 `연동 확인용 테스트 공간 · 임태빈` 대관 일정이 캘린더에 나타나는 것을 확인했다.

`attendance.html`은 GitHub Pages 공개 주소에서 요일 선택·동아리·인원 순서의 출석 시작 화면을 정상 표시했다. `admin.html`은 프로그램·사진 관리 화면을 바로 노출하지 않고 관리자 비밀번호 입력 단계로 먼저 열려, 공개 페이지와 관리자 진입이 분리된 것을 확인했다.

관리자 비밀번호 검증을 실제로 시도한 결과, 현재 배포된 Apps Script는 `verifyAdminPassword` 요청에 `지원하지 않는 요청입니다.`라고 응답했다. GitHub Pages 정적 관리자는 정상 배포됐지만 Apps Script 웹 앱이 관리자 API가 들어간 최신 `Code.gs` 버전으로 아직 재배포되지 않은 상태다. 따라서 Code.gs 교체, 두 스크립트 속성 확인, 새 웹 앱 버전 배포가 남아 있다.

사용자 재배포 후에도 같은 POST 요청을 GitHub Pages 브라우저에서 다시 실행했으며, 응답은 여전히 `{"error":"지원하지 않는 요청입니다."}`였다. 반면 `health`는 응답하므로 `/exec` 주소 자체는 열려 있다. 이는 현재 공개된 웹 앱 버전에 관리자 API 분기가 포함되지 않았거나, 최신 Code.gs가 다른 Apps Script 프로젝트에 반영된 상태임을 의미한다.

이후 Apps Script의 `ADMIN_GATE_PASSWORD` 속성을 `0226`으로 저장한 뒤, 같은 `verifyAdminPassword` POST 요청이 `{"ok":true,"valid":true}`로 응답하는 것을 확인했다. GitHub Pages `admin.html`에서도 관리자 로그인에 성공했으며, 새 프로그램·임시저장·공개 저장·사진 선택·저장된 프로그램 목록으로 구성된 프로그램 관리 화면이 실제로 열렸다.

사용자 승인 하에 68바이트 PNG 테스트 이미지를 관리자에서 업로드했으나, Apps Script는 `DriveApp.getFoldersByName` 실행 권한이 없다는 오류를 반환했다. 관리자 API·비밀번호·프로그램 시트 조회는 정상이며, 남은 조치는 Apps Script 소유 계정에서 DriveApp 권한을 한 번 승인하는 것이다.

DriveApp 권한 승인 후 동일 PNG를 다시 업로드해 `사진을 Google Drive에 저장했습니다.` 안내를 확인했다. 관리자 폼의 대표 사진 URL에는 Google Drive 공개 썸네일 주소가 반환되어 이미지 저장·공개 URL 생성·프로그램 연결 준비까지 정상 동작함을 확인했다.

업로드된 Drive 대표 사진 URL을 포함해 관리자 **미리보기**를 열었고, 공개 전 미리보기 안에서 해당 이미지와 기본 프로그램 정보가 표시되는 것을 확인했다. 테스트 이미지 파일은 Drive에 저장됐으나, 아직 프로그램 시트 행으로 저장하거나 공개하지는 않았다.

사용자 승인 후 `연동 확인용 테스트 프로그램`을 **임시저장 · 비공개**로 저장했다. 관리자 목록에서 해당 행이 표시됐고, 공개 `getPrograms` 조회 결과에는 포함되지 않아 비공개 저장·대표 사진 URL 연결·공개 전 차단 흐름이 정상 동작함을 확인했다.

## 2026-08-18: 휴대폰 프로그램 카드 2열

프로그램 안내의 GitHub Pages 정적 화면에 모바일 전용 스타일시트를 추가해 800px 이하에서 프로그램 카드가 `repeat(2, minmax(0, 1fr))` 2열 그리드로 배치되도록 변경했다. GitHub Actions Pages 배포가 성공했고, 공개 `programs.html`에서 최신 모바일 스타일시트가 실제로 로드되는 것을 확인했다. 현재 공개 프로그램은 없으므로 카드 콘텐츠 대신 빈 상태가 보이지만, 다음 공개 프로그램부터 두 장씩 나란히 표시된다.

프로그램 카드의 일정은 상단 분류 정보에서 분리해 카드 하단의 구분선 아래로 이동했다. 휴대폰 2열 카드에서는 일정 라벨과 날짜를 세로로 배치해 제목·소개 영역과 겹치지 않도록 했다. 375px 폭의 프로그램 안내 화면에서 전체 필터·목록 레이아웃이 유지되는 것을 확인했다.

## 2026-08-18: GitHub Pages 홈 화면 구성 보완

GitHub Pages의 정적 홈 화면이 미리보기보다 단순하게 보이던 상태를 보완했다. 서비스 카드에 기능별 선형 아이콘과 동작 문구를 복원하고, 남양주문화재단·동아리 활동 일정 확인·대관 확인 바로가기를 하단에 추가했다. 데스크톱 제목의 최대 폭 제한을 제거해 넓은 화면에서는 한 줄로 표시되게 했으며, GitHub Actions Pages 배포 성공과 공개 화면의 9개 링크를 확인했다.

## 2026-08-18: 정적 화면 타이포그래피 정렬

GitHub Pages 정적 화면이 미리보기와 다른 기본 시스템 글꼴·간격을 사용하던 문제를 보완했다. SUIT와 KRDS형 16px 본문, 1.6 행간, 1200px 콘텐츠 폭, 76px 헤더, 카드·바로가기의 동일한 글자 크기와 여백 기준을 공통 스타일로 정의했다. 빌드 단계가 홈페이지·프로그램 목록·상세·관리자 화면에 공통 스타일을 자동 주입하도록 구성했으며, GitHub Actions 배포 후 공개 홈페이지에서 적용을 확인했다.
